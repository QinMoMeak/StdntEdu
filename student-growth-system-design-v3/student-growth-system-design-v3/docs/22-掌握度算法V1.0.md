# 掌握度算法 V1.0

## 1. 适用范围与版本

本文件冻结学生知识点掌握度算法 `1.0`。算法版本来自 `system_config` 的
`mastery.algorithm.version`。任何会改变相同证据重放结果的规则都必须升级算法版本，不能静默修改 V1.0。

V1.0 只计算具体知识点自身，不计算父节点平均值，不向父节点或子节点传播，不使用 AI、学习资源、学习计划或 Dashboard 推断。

掌握度记录由 `(student_id, knowledge_id)` 唯一定位。数据库使用 `Long` ID，API 使用 `string` ID。

## 2. 数值规范

- `mastery_score` 范围为 `0.00` 至 `100.00`。
- 核心计算统一使用 `BigDecimal`，禁止使用 `double` 进行持久化计算。
- 比率计算使用 scale 8、`RoundingMode.HALF_UP`；事件分类使用该比率。
- 每个事件应用后的分数使用 scale 2、`RoundingMode.HALF_UP`。
- 每个事件后将分数 clamp 到 `[0.00, 100.00]`。
- `score_before`、`change_value`、`score_after` 使用相同的 scale 2，且必须满足
  `change_value = score_after - score_before`。

## 3. 配置来源

所有参数从 `system_config` 读取，不在 Java 代码中散落常量。

### 3.1 算法与分类

| 配置键 | V1.0 默认值 | 用途 |
|---|---:|---|
| `mastery.algorithm.version` | `1.0` | 算法版本 |
| `mastery.score_rate.correct_min` | `0.80` | EXAM 的 CORRECT 下限，包含边界 |
| `mastery.score_rate.partial_min` | `0.60` | EXAM 的 PARTIAL 下限，包含边界 |
| `mastery.time_decay.enabled` | `false` | 时间衰减开关 |
| `system.timezone` | `Asia/Shanghai` | 事件日期和每日限幅的时区 |

### 3.2 第一条有效事件初始值

| 配置键 | 默认值 |
|---|---:|
| `mastery.initial.correct` | `60` |
| `mastery.initial.partial` | `45` |
| `mastery.initial.wrong` | `30` |
| `mastery.initial.unknown` | `20` |

### 3.3 后续事件增量

| 证据来源 | 结果 | 实际配置键 | 默认值 |
|---|---|---|---:|
| EXAM | CORRECT | `mastery.change.exam.correct` | `10` |
| EXAM | PARTIAL | `mastery.change.exam.partial` | `4` |
| EXAM | WRONG | `mastery.change.exam.wrong` | `-12` |
| PRACTICE | WRONG | `mastery.change.practice.wrong` | `-8` |
| REVIEW | CORRECT | `mastery.change.review.correct` | `8` |
| REVIEW | PARTIAL | `mastery.change.review.partial` | `3` |
| REVIEW | WRONG | `mastery.change.review.wrong` | `-10` |
| REVIEW | UNKNOWN | `mastery.change.review.unknown` | `-14` |

V13 还存在 `mastery.change.practice.correct=6` 和
`mastery.change.practice.partial=2`。V1.0 的 PRACTICE 仅指错题基础事件，结果固定为 WRONG，因此这两个键在 V1.0 不参与重放，保留供未来有明确练习结果的数据源使用。

### 3.4 变化限制

| 配置键 | 默认值 | 含义 |
|---|---:|---|
| `mastery.max_increase_per_event` | `15` | 单次最大正变化 |
| `mastery.max_decrease_per_event` | `20` | 单次最大负变化的绝对值 |
| `mastery.max_daily_increase` | `20` | 每个本地自然日最大累计正变化 |
| `mastery.max_daily_decrease` | `25` | 每个本地自然日最大累计负变化的绝对值 |

`mastery.ai_min_confidence` 不参与 V1.0，因为 V1.0 禁止使用 AI 证据。

### 3.5 现有复习配置

`review.interval.days`、`review.auto_master_stage`、
`review.auto_master_continuous_correct`、`review.auto_master_score`、
`review.max_interval_days` 和 `review.max_daily_questions` 继续用于错题复习调度。
V1.0 不用这些配置直接推导 `student_mastery.next_review_time`。

## 4. 有效证据

### 4.1 EXAM

EXAM 从 `score_knowledge` 获取，并通过
`score_knowledge -> score_record -> exam` 关联到学生。只使用 `exam.deleted=0`、
`score_record.deleted=0` 且知识点匹配的记录。

比率按以下优先级计算：

1. `score` 和 `full_score` 非空且 `full_score > 0` 时，使用 `score / full_score`。
2. 否则，`correct_count` 和 `question_count` 非空且 `question_count > 0` 时，使用
   `correct_count / question_count`。
3. 两种方式均不可用时，该记录不是有效证据。

分类规则：

- `rate >= mastery.score_rate.correct_min`：CORRECT。
- `mastery.score_rate.partial_min <= rate < mastery.score_rate.correct_min`：PARTIAL。
- `rate < mastery.score_rate.partial_min`：WRONG。

事件时间取 `exam.exam_date` 在 `system.timezone` 当日 `00:00:00`；业务 ID 为
`score_knowledge.id`。同一知识点允许多次考试证据，每条有效 `score_knowledge` 独立形成一个事件。

### 4.2 PRACTICE

每条 `wrong_question.deleted=0` 且通过 `wrong_question_knowledge` 关联到当前知识点的错题形成一个 PRACTICE 事件，结果固定为 WRONG。

事件时间优先取 `wrong_question.occurred_date` 在系统时区当日 `00:00:00`；为空时取
`wrong_question.create_time`。业务 ID 为 `wrong_question.id`。

一条错题关联多个知识点时，对每个关联知识点都形成一条完整证据，不进行 `1/N` 分摊。
V1.0 不人为构造 `knowledge_weight`。

### 4.3 REVIEW

REVIEW 从 `wrong_review` 获取，必须经
`wrong_review -> wrong_question -> wrong_question_knowledge` 关联到学生和知识点。
结果直接使用 CORRECT、PARTIAL、WRONG 或 UNKNOWN；UNKNOWN 不得按 CORRECT 处理。

事件时间取 `wrong_review.review_time`，业务 ID 为 `wrong_review.id`。每条有效复习独立形成一个事件，不能把 `wrong_question.review_count` 再次展开为重复证据。

## 5. 删除与归档

- `wrong_question.deleted=1`：排除错题基础事件，并排除其下全部 REVIEW 事件；
  `wrong_review` 业务历史数据仍保留。
- `wrong_question.status=ARCHIVED` 且未删除：不进入未来 due review，但既有 PRACTICE
  和 REVIEW 掌握度证据继续有效。
- 删除考试时，`exam.deleted=1` 和 `score_record.deleted=1` 使对应 EXAM 证据失效；
  `score_knowledge` 可保留但不参与重放。

## 6. 确定性重放顺序

全部有效事件按以下键升序排列：

1. `eventTime ASC`。
2. 时间完全相同时，来源优先级为 EXAM、PRACTICE、REVIEW。
3. 来源也相同时，`businessId ASC`。

相同底层证据和配置必须产生完全相同的排序和结果。

## 7. 分数重放公式

若有效事件为空，不创建自动 `student_mastery` 记录，也不写入默认分数。

第一条有效事件直接使用对应的 `mastery.initial.*` 值初始化，不叠加来源增量，也不应用单次或每日限幅；初始化值仍需 scale 2 并 clamp 到 `[0,100]`。

从第二条事件开始，逐条执行：

1. 按来源和结果读取 `mastery.change.*` 原始增量。
2. 正增量限制到 `mastery.max_increase_per_event`；负增量绝对值限制到
   `mastery.max_decrease_per_event`。
3. 按 `system.timezone` 将事件归入本地自然日。
4. 将正增量限制到该日尚余的 `mastery.max_daily_increase`；将负增量绝对值限制到该日尚余的 `mastery.max_daily_decrease`。
5. 将受限增量加到当前分数，scale 2、HALF_UP，并 clamp 到 `[0,100]`。
6. 每日累计量使用本次 clamp 后的实际分数变化，不使用被边界截断前的理论增量。

最终重放分数就是最后一个事件后的分数。

## 8. 计数与连续结果

- `evidence_count`：实际参与重放的有效事件总数，包括有效 EXAM、PRACTICE、REVIEW
  和 UNKNOWN REVIEW。
- `correct_count`：全部有效 CORRECT 事件数。
- `partial_count`：全部有效 PARTIAL 事件数。
- `wrong_count`：全部有效 WRONG 事件数，不包含 UNKNOWN。
- `review_count`：全部有效 REVIEW 事件数，包含 UNKNOWN。
- `continuous_correct_count`：从最后事件向前连续 CORRECT 的数量；遇到非 CORRECT 即停止。
- `continuous_wrong_count`：从最后事件向前连续 WRONG 的数量；遇到非 WRONG 即停止。

无效 `score_knowledge`、已删除错题及其 review 链、无知识点关联的数据不计入
`evidence_count`。

## 9. 时间字段

- `last_practice_time`：有效 EXAM 或 PRACTICE 事件中最大的 `eventTime`。
- `last_review_time`：有效 REVIEW 事件中最大的 `eventTime`。
- `decay_base_time`：全部有效自动证据中最后一个事件的 `eventTime`。
- `next_review_time`：当前学生和知识点关联的、`deleted=0` 且状态不是 ARCHIVED 的
  `wrong_question.next_review_time` 中最小的非空值；没有符合条件的错题时为 NULL。

`student_mastery.next_review_time` 表示知识点层面最早相关错题的待复习时间，不等同于任何随机错题的时间，也不使用 `review.interval.days` 重新推导。

## 10. 时间衰减

V1.0 要求 `mastery.time_decay.enabled=false`，不对 `mastery_score` 做时间衰减。
`decay_base_time` 只记录未来算法可能使用的基准时间。启用或定义衰减函数必须升级算法版本。

## 11. 人工调整与锁定

`adjustKnowledgeMastery` 通过请求中的 `studentId` 和路径中的 `knowledgeId` 唯一定位记录：

1. 校验学生、知识点、目标分数、必填 reason 和 version。
2. 将目标分数按 scale 2、HALF_UP 写入 `mastery_score`。
3. 设置 `manual_locked=true`；V1.0 的 `lockResult` 必须为 true。
4. 记录 MANUAL_ADJUST 历史，`manual_flag=true`，remark 记录 reason。
5. 已有记录必须匹配 version；不存在记录时只接受 version=0，并以计数均为 0 的人工锁定记录创建。

锁定期间自动重放仍更新所有计数字段、证据时间、`decay_base_time` 和
`next_review_time`，但保留人工分数，不得用自动重放结果覆盖 `mastery_score`。

## 12. 解锁

`unlockKnowledgeMastery` 通过必填 query `studentId` 和路径 `knowledgeId` 唯一定位记录：

1. 收集全部当前有效证据并重放。
2. 若 `evidence_count=0`，返回 HTTP 409、错误码 `BUSINESS_RULE_VIOLATION`；不清除锁、不创建默认分数。
3. 有有效证据时设置 `manual_locked=false`，立即写入自动重放分数、计数和时间字段。
4. 写 MANUAL_UNLOCK 历史；`manual_flag=true`。即使重放分数与锁定分数相同，也保留一次解锁历史，变化量为 `0.00`。

解锁不接受隐式学生上下文。当前尚未实现真实 JWT，必须显式提供 `studentId`。

## 13. mastery_history 写入

以下情况写入不可变历史：

- 自动重放使实际 `mastery_score` 改变：`event_type=AUTO_REPLAY`、`manual_flag=false`。
- 人工调整：`event_type=MANUAL_ADJUST`、`manual_flag=true`。
- 人工解锁：`event_type=MANUAL_UNLOCK`、`manual_flag=true`。

自动重放只更新计数或时间、但分数未改变时不写分数历史。历史记录不更新、不覆盖、不删除。

`business_type` 记录触发来源 EXAM、WRONG_QUESTION、WRONG_REVIEW 或 MANUAL；能唯一对应单个触发业务时写 `business_id`，批量重算时允许为空。

`calculation_detail_json` 至少记录：

- `algorithmVersion`
- `trigger`
- `evidenceCount`
- 各结果和来源事件数量
- 本次使用的配置快照
- 自动重放结果
- 重放前后锁定状态

没有真实业务值时，`difficulty_factor`、`confidence`、`knowledge_weight` 和
`streak_adjustment` 写 NULL，不得为了填充字段虚构 `1.0`。

## 14. 重算触发与事务

内部能力 `recalculateMastery(studentId, knowledgeId)` 只重算指定聚合；
`recalculateAffectedMastery` 对去重后的受影响 knowledgeId 集合逐项重算，禁止全表扫描。

后续阶段接入触发点：

- 创建、更新或删除含 `score_knowledge` 的考试。
- 创建、更新知识点集合或删除错题。
- 提交 `wrong_review`。

集合从 A 改为 B 时必须重算旧集合和新集合的并集。业务写入、当前掌握度更新和历史写入必须处于一致事务边界；任何一步失败都整体回滚。

## 15. 并发与幂等

`student_mastery` 依赖 `(student_id, knowledge_id)` 唯一约束防止重复当前记录，并使用
`version` 乐观锁防止静默覆盖。并发首次创建发生唯一键冲突时，业务层应重新读取后按当前证据重算，不得泄漏数据库异常或静默吞掉失败。

相同底层证据、相同配置和相同算法版本重复重放时，以下字段必须完全一致：

- `mastery_score`
- 所有结果计数和连续计数
- `evidence_count`
- `last_practice_time`
- `last_review_time`
- `decay_base_time`
- `next_review_time`

幂等重放若没有改变实际分数，不重复写 AUTO_REPLAY 历史。
